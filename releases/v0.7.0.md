# v0.7.0 — must-reference 강제 참조 스니펫 (Claude Code · Cursor)

- **날짜**: 2026-05-26
- **유형**: MINOR
- **이전**: v0.6.0
- **검증 상태**: 부분 검증 통과 — 자산 sync ✅ / 주입 로직은 ops-pilot 보강 대기

## 이 릴리스는

소비 프로젝트의 LLM이 agent-crew 자산을 **호출 자체를 안 하면** 무용지물이 되는 한계를 보강한다.
우아한형제들 기술블로그 ["MCP stdio로 헤쳐모여!"](https://techblog.woowahan.com/25986/) 글이 지적한
*"에이전트가 필요하지 않다고 판단하면 실행되지 않는다"* 문제에 대한 대응.

**Level 2 강제** (always-injected `MUST` 명령) — Claude Code의 `CLAUDE.md`와 Cursor의 `alwaysApply: true` 룰
양쪽에 동일한 강제 참조 블록을 박는다. 본문은 동일하고 포장지만 다르다.

## 자산별 변경

### `references/conventions/must-reference/` — 신규

- **변경**: 디렉토리 신설. 3개 파일
  - `README.md` — 왜·언제·어떻게 (강제의 3단계, 두 IDE 지원, 자산 선택 흐름)
  - `claude-md-snippet.md` — Claude Code 소비 프로젝트의 `CLAUDE.md`에 박을 `<!-- agent-crew:must-reference -->` 마커 블록 템플릿
  - `cursor-always-rule.mdc` — Cursor용 `.cursor/rules/agent-crew-must.mdc` (frontmatter `alwaysApply: true`, `globs: ["*"]`)
- **개선**: 매 요청마다 LLM이 "agent-crew 4원칙 + 활성화된 컨벤션"을 인지하게 됨. 자산 호출 누락 확률 대폭 감소.
- **동기**: Level 1(권고) 수준의 권유는 무시되기 쉬워, 호출 보장 없이 자산을 만들어도 효과가 약함.

### `project.yaml.example` — 선택적 블록 추가

- **변경**:
  - `project.ide` 신설 — `claude-code | cursor | both`
  - `agentCrew.mustReference` 신설 — 배열. 강제 참조할 자산 키 목록. 기본 권장은 `work-evaluator-4-principles` 하나.
  - `agentCrew.version` 갱신: `v0.4.0` → `v0.7.0`
- **개선**: 소비 프로젝트가 IDE·강제 항목을 명시 → ops-pilot이 sync 시 정확한 스니펫을 정확한 위치에 배포 가능
- **호환성**: 기존 소비 프로젝트는 새 키 미설정 시 스니펫 배포 안 됨 (안전한 기본값)

## 검증 (외부 — ops-pilot 세션)

**일자**: 2026-05-27 · **대상**: spring-platform-commons

### 부분 통과 — 자산 자체는 valid, 주입 계약은 ops-pilot 미구현

| 항목 | 결과 | 책임 |
|---|---|---|
| 자산 파일 sync (스니펫·README) | ✅ `.claude/references/conventions/must-reference/`로 정상 복사 | agent-crew OK |
| `project.yaml`의 `ide`·`mustReference` 키 스키마 | ✅ 키 추가 가능 | agent-crew OK |
| **CLAUDE.md 마커 블록 자동 주입** | ❌ ops-pilot `sync.ts`에 주입 로직 0건 (grep 0) | **ops-pilot 보강 필요** |
| Cursor `.mdc` 자동 배포 | ❌ 동일 사유 | **ops-pilot 보강 필요** |
| 재실행 시 idempotent | (주입 로직 부재로 미측정) | ops-pilot 보강 후 재검증 |

→ v0.7.0의 *자산*은 valid. 주입 동작은 ops-pilot sync.ts 보강 후 재검증 예정.

### 검증 시나리오 (ops-pilot 보강 후 재실행 대상)

1. `project.yaml.ide: claude-code` + `mustReference: [work-evaluator-4-principles]` → 소비 프로젝트 `CLAUDE.md` 맨 위에 마커 블록 idempotent 삽입
2. `ide: cursor` → `.cursor/rules/agent-crew-must.mdc` 생성
3. `ide: both` → 둘 다
4. `mustReference`에 `commit-format` 추가 → 마커 블록의 "활성화된 컨벤션"에 해당 줄 동적 포함
5. 재실행 시 변경 없음 (idempotent)
6. 마커 블록 외부의 기존 `CLAUDE.md` 내용 보존 확인

### 부수 발견 (ops-pilot 세션 보고)

- **다운그레이드 함정**: `project.yaml.agentCrew.version`이 `.claude/agent-crew.lock`의 버전보다 신버전이어도 ops-pilot이 lock으로 다운그레이드. 신버전 sync는 tag override 명시 필요. → ops-pilot 측 정책 수정 권고 전달됨.
- **ops-pilot 자가 sync 정지**: ops-pilot 자체 lock이 `v0.6.0`에 멈춤. ops-pilot 자가 sync로 v0.9.1까지 따라와야 함.

## 호환성

- **project.yaml**: 신규 키 `project.ide`, `agentCrew.mustReference` 모두 선택적. 기존 프로젝트 변경 불필요.
- **마이그레이션**: 강제 참조를 켜려는 프로젝트만 두 키를 채우고 ops-pilot sync 1회.

## 한계 (의도된)

- LLM이 본문을 보고도 의식적으로 무시할 수 있다 (확률은 매우 낮음). 100% 보장은 Hook 레벨(Level 3)에서만 가능.
- 매 요청에 토큰 소비 — 따라서 본문 전체가 아닌 "참조 명령 + 4원칙 4줄"만 박는다.
  - **단, prompt caching 시대 보정**: Anthropic prompt caching(5분 TTL, 캐시 hit 시 입력 토큰 비용 ~10%)을 고려하면 같은 세션 내 후속 요청은 must-reference 블록이 거의 무료. cold start만 풀 비용이므로, 향후 본문을 더 풍부하게 가져갈 여지가 있다 (별도 평가 필요).
  - 근거: [ryu-qqq-wiki/research/agent-engineering/30-anthropic-official.md](https://github.com/ryu-qqq/ryu-qqq-wiki/blob/main/wiki/research/agent-engineering/30-anthropic-official.md) D항
- Hook 기반 강제는 [Agent Engineering 트렌드 조사 → 평가 프레임워크] 에픽 결과 후 별도 진행.
