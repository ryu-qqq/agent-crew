# v0.16.0 — review-ledger 스킬: 수용된 리뷰 지적을 실수 원장에 적립

- **날짜**: 2026-06-11
- **유형**: MINOR
- **이전**: v0.15.0
- **검증 상태**: e2e dogfooding 통과 — 실제 리뷰된 PR(agent-crew#3, 수용 2건)로 스킬 5단계를 완주: 책임 자산 식별(harness-author) → HITL 선별 → 중복 확인 → 시나리오 2건 적립(`list_scenarios` 확인) → vault 시드 기록. 이 과정에서 문서의 엔드포인트 오기(`/scenarios`→`/api/scenarios`)를 발견·수정. trigger-eval은 별도 미검증.

> 이 파일은 `releases/TEMPLATE.md`를 복사해 채웁니다. 작성·태그 절차는 VERSIONING.md "릴리스 기록" 참조.

## 이 릴리스는

PR 리뷰에서 **수용된(타당하다고 판단된) 지적은 사람이 직접 단 라벨**이라는 통찰에서 출발합니다 — "이 작업은 이렇게 하면 틀린다"는 가장 비싼 신호인데, 리뷰가 닫히면 그대로 증발합니다. `review-ledger`는 그 신호를 실수 원장에 적립합니다: ① 책임 자산에 OpsPilot 베드케이스 시나리오 등록(이후 자산이 바뀔 때마다 "이 실수를 다시 하나"가 자동 평가) ② vault raw 시드 기록 ③ 같은 유형 지적이 반복되면 자산 개선 proposal 초안까지.

pr-review-triage(v0.15.0)가 "리뷰를 읽고 판단"하는 스킬이라면, review-ledger는 그 판단 결과를 **학습 루프에 적립**하는 후속 스킬입니다 — 둘이 합쳐 "리뷰 → 판단 → 적립 → 재발 방지"의 Loop 2(실수 원장)가 완성됩니다.

## 자산별 변경

### `skills/review-ledger/SKILL.md` — 신규

- **변경**: 적립 전담 스킬. 5단계 — 입력 확정(triage 결과 또는 사용자 목록, 없으면 triage 안내 후 멈춤) → 책임 자산 식별(모호하면 질문) → 적립 대상 선별(HITL — 권장·이유 표 제시, 선택은 사람) → 시나리오 적립(OpsPilot `:3001` REST, 중복 조회 선행, `review-ledger:` name prefix, judge는 실수 *유형*으로 일반화) → 시드 기록+반복 감지(append-only ledger 시드, 같은 유형 2회+면 proposal 초안 JSON).
- **개선**: 신규. 그동안 리뷰 지적은 해당 PR에서 소비되고 끝 — 같은 실수를 다음 작업에서 반복해도 잡을 장치가 없었습니다. 자산화로 사람의 리뷰가 평가 데이터(시나리오)와 자산 개선(proposal)으로 복리 적립됩니다.
- **동기**: "사람이 굿/베드 케이스를 라벨링해야 평가가 의미 있다"는 결론과 "PR 리뷰가 바로 그 라벨"이라는 통찰의 결합. 어느 프로젝트의 PR 리뷰에서나 재발하는 패턴이라 공유 자산이 적합합니다.
- **설계 못박음**: ⓐ **적립 전담** — 리뷰 수집·판단은 pr-review-triage, proposal 검토·적용은 proposal-reviewer/applier, 이 스킬은 그 사이의 적립만. ⓑ **재료 게이트** — triage 결과 없이 호출되면 스스로 리뷰를 수집·판단하지 않고 멈춤(가장 흔한 오작동 차단). ⓒ **전부 적립 금지** — 일회성·맥락 한정 지적은 시나리오화하면 평가 노이즈. 선별은 사람(HITL). ⓓ **judge 일반화** — 지적 원문 복사가 아니라 실수 유형 기준("X 파일 42줄 가드"가 아니라 "외부 입력 무검증 금지")으로 — 특정 PR에만 유효한 죽은 테스트 방지. ⓔ **프로젝트 비종속** — vault 경로·rawPrefix는 project.yaml, OpsPilot projectId는 list_projects/사용자 확인.

### `CHANGELOG.md` — 인덱스 갱신

## 검증 (ops-pilot)

> agent-crew는 평가를 *실행*하지 않습니다 — 검증은 ops-pilot에서. 아래는 trigger-eval 입력 후보입니다.

**should-trigger (5)**

1. "방금 pr-review-triage 돌린 결과에서 수용으로 분류된 지적 3개, 원장에 적립해줘"
2. "이번 PR에서 N+1 쿼리 지적 받았는데 같은 실수 또 안하게 등록 좀"
3. "review ledger에 이 리뷰 코멘트 올려줘. @Transactional 경계 빠뜨린 거"
4. "어제 받은 리뷰 학습시켜줘, 다음부터는 같은 거 안 틀리게"
5. "이 보안그룹 0.0.0.0/0 지적 벌써 세 번째인데 베드케이스 시나리오로 만들어서 적립해줘"

**should-NOT-trigger (5, near-miss)**

1. "이 PR에 리뷰 코멘트 잔뜩 달렸는데 뭐가 맞는 지적인지 봐주고 뭐부터 고칠지 정리해줘" → pr-review-triage
2. "동료가 올린 terraform 모듈 PR에 리뷰 좀 남겨줘" → 리뷰 작성
3. "harness-author가 올린 proposal 타당한지 검토해줘" → proposal-reviewer
4. "오늘 observability 알람 작업한 거 회고로 기록해줘" → journal
5. "ops-pilot 평가용 시나리오 하나 만들어줘, ECS 배포 실패 케이스로" → scenario-designer

**시나리오 기반 검증 — 통과 (2026-06-11)**: agent-crew#3 리뷰의 수용 2건으로 e2e 완주. harness-author 자산에 "공유 저장소 읽기/쓰기 패턴 비대칭"·"참조 포맷 enum 값 누락" 베드케이스 적립(`list_scenarios` 확인), vault ledger 시드 기록. 부수 효과로 본문 엔드포인트 오기(`/api` prefix 누락) 발견·수정 — 스킬이 자기 e2e에서 첫 가치를 냈다.
