- **날짜**: 2026-05-27
- **유형**: MINOR
- **이전**: v0.7.0

## 이 릴리스는

agent-crew의 모든 자산(agents·skills·references·hooks·cursor rules)을 **구조 품질 8차원으로 채점**하는 메타 평가 자산을 신설한다. work-evaluator가 *작업의 4축*을 본다면, agent-evaluator는 *자산 구조의 8차원*을 본다 — 두 평가는 직교.

근거 사슬: `asset-quality-rubric.md` → [ryu-qqq-wiki/wiki/research/agent-engineering/99-evaluation-framework.md](https://github.com/ryu-qqq/ryu-qqq-wiki/blob/main/wiki/research/agent-engineering/99-evaluation-framework.md) → 10·20·30·40·50번 조사 노트 (우아한·토스·당근·네이버 + agents.md·MCP·Skills + Anthropic Hooks·Caching·Context Engineering + SWE-bench·BFCL·GAIA·Tau-bench·Multi-agent + Lost in the Middle).

## 자산별 변경

### `agents/agent-evaluator.md` — 신규

- **변경**: 8차원 rubric 실행 에이전트. 자산 유형 분류 → 호출자/피호출자 구분 → Step A 정성 + Step B 정량(LLM only) → JSON 결과 + vault evaluation 시드 append
- **개선**: ops-pilot이 sync·PR 검증 시 자산 release 정책을 자동화할 수 있는 입력(verdict) 제공
- **동기**: 자산이 12개 agents · 다수 skills로 늘면서 *"이게 좋은 자산인가"* 판단 도구 부재
- **참고**: work-evaluator (작업 4축)와 직교. 둘 다 같은 자산에 적용 가능, 다른 층위.

### `references/conventions/asset-quality-rubric.md` — 신규

- **변경**: 8차원 × 1~5점 채점 SSOT. 자산 유형 매트릭스 + 호출자/피호출자 분류 + verdict 임계값(release-pass / improve-recommended / reevaluate / redesign)
- **개선**: agent-evaluator가 실행할 rubric을 본문에서 분리 → rubric 갱신과 에이전트 갱신 디커플링

### `lab/evaluations/2026-05-27-work-evaluator-manual.md` — 신규 (참조용)

- **변경**: agent-evaluator 구현 *전*에 사람이 work-evaluator.md를 8차원 rubric으로 수동 채점한 결과
- **개선**: rubric의 6가지 모호함을 LLM evaluator로 넘어가기 전에 발견·정정 (silver bullet 함정 회피)
- **결과**: work-evaluator 종합 26/40 (improve-recommended-release 영역) + rubric 피드백 6건이 99번 정정에 반영됨

### git tag 정책 — Option B 채택

자가검증은 본질적 한계 (자기 자신을 평가 → 거짓 양성 위험 + 차원 4·7 메타 한계). 32점은 마지노선.

→ **main 머지는 진행, git tag는 외부 검증 후로 미룸**:
- (a) proposal-reviewer 또는 다른 자산을 agent-evaluator로 채점 → 일관성 확인
- (b) ops-pilot에서 실제 실행 → JSON 출력 정상 확인
- (c) 위 둘 결과를 본 release에 추가 기록 후 git tag

이는 *"검증 후 태그"* 정책과 정합 — 자가검증만으로는 검증 사이클 절반.

### 자가검증 결과로 발견된 추가 rubric 피드백 2건

99번 후속 정정 대상 (v1.1 예정):
- **§7** — 평가 자산 자체의 차원 4·7은 본질적 한계 (LLM-as-Judge가 자기 LLM-as-Judge 평가). "메타 평가는 항상 외부 검증 동반" 원칙 명시 필요
- **§8** — 피호출자 채점 시 호출자가 다른 레포에 있는 경우 채점 한계 (정보 부재 시 기본 3점)

### ops-pilot 검증 시나리오 (다음 단계)

1. agent-evaluator로 proposal-reviewer 채점 → 사람 채점과 일치도 확인
2. 기존 12개 agents 채점 → 점수 분포 보고
3. 점수 < 24인 자산 (`reevaluate-required`) 식별 → 개선 우선순위
4. sync 시 verdict가 `release-pass` 미만이면 release 보류 정책 검토
5. 위 단계 완료 후 git tag v0.8.0

## 한계 (의도된)

- **rubric은 하한선 도구** — 점수 높음 = "기본은 갖춤", 실효는 사람 검토 결합 필수
- **Pass^k 정량 측정은 LLM evaluator만** — 사람 수동 채점에선 Step A로만
- **Claude Code 종속 자동 실행** — Cursor 환경은 사람 수동 채점 또는 CI 자동화로 (P3 에픽: GitHub Action CI)
- **자가검증이 거짓 양성일 수 있음** — 자기 자신을 후하게 채점할 가능성. 별도 자산(예: proposal-reviewer)도 채점해 일관성 교차검증 권장
