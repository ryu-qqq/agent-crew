# v0.17.0 — review-ledger: proposal 초안 텍스트 제시 → ops-pilot 자동 적립

- **날짜**: 2026-06-28
- **유형**: MINOR
- **이전**: v0.16.0
- **검증 상태**: 미검증

## 이 릴리스는

`review-ledger` 스킬이 반복 패턴 감지 시 "proposal 초안을 텍스트로 제시(사람이 복붙·수동 적용)"하던 흐름을, ops-pilot 신규 엔드포인트(`POST /api/feedback/review-proposal`)로 **자동 적립**하는 흐름으로 교체합니다.

HITL 경계는 그대로 유지 — 어떤 proposal을 적립할지 선별은 사람이 하고, 에이전트는 선택된 항목만 POST합니다. proposal은 ops-pilot에 `draft`로 들어가며 approve·apply는 사람이 ops-pilot 인박스에서 합니다. "복붙 후 수동 적용"이라는 마찰이 제거되어 PR 리뷰 → 실수 원장 → 자산 개선 루프가 닫힙니다.

## 자산별 변경

### `skills/review-ledger/SKILL.md` — 개선

- **변경**:
  - 흐름 §5 반복 감지: `POST /api/feedback/review-proposal` 호출 절차 추가 (HITL 선별 표 → POST → 응답 처리 · 안내)
  - payload 구조 명시: `{ projectId, targetKind, targetPath, rationale, content, review:{prNumber,repo,commentUrl,reviewer,mistakeType}, scenarioId? }`
  - `scenarioId`는 4단계 `POST /api/scenarios` 응답 값으로 시나리오–proposal 연결
  - 결과 안내: "텍스트 복붙" → "ops-pilot 인박스에서 검토·승인하라"로 교체
  - HITL 경계: `proposal 초안 작성` → `proposal 초안 구성 · 선택된 proposal ops-pilot 적립(POST)`으로 갱신
  - 산출물: `proposal 초안 JSON` → `{ ingestId, proposalId } 목록 + 인박스 확인 안내`로 갱신
  - 역할 §3: `proposal 초안 제시` → `proposal draft 자동 적립`으로 갱신
  - `projectId` 사용 범위: 자산 식별(2단계) 외 proposal 적립(5단계)에도 쓴다고 명시
- **개선**: v0.16.0에서 반복 패턴 감지 후 proposal 초안을 텍스트로 제시하면 사람이 직접 복붙·수동 적용해야 했습니다. 이번 변경으로 선택된 proposal이 ops-pilot `draft`로 자동 적립되어 루프가 코드 없이 닫힙니다.
- **동기**: ops-pilot에 `POST /api/feedback/review-proposal` 엔드포인트가 신설(Task 4)되어 스킬이 직접 POST할 수 있게 됨.
