# v0.9.0 — context-preprocessor skill + java-spring 추출 가이드

- **날짜**: 2026-05-27
- **유형**: MINOR
- **이전**: v0.8.0
- **검증 상태**: 검증 통과 — context-preprocessor 자가 34/40 + work-evaluator·proposal-reviewer 차원 1 +1 향상 실증

## 이 릴리스는

우아한형제들 *하네스 엔지니어링* 글(96.5% 토큰 절감)의 **전처리 스크립트 패턴**을 agent-crew 자산으로 직접 구현합니다. agent가 무거운 코드 탐색 시 원본을 통째 Read 하지 않고, 정제 JSON 메타데이터만 받게 하는 skill 신설.

근거 사슬:
- [10-industry-cases.md A3](https://github.com/ryu-qqq/ryu-qqq-wiki/blob/main/wiki/research/agent-engineering/10-industry-cases.md) — 우아한 96.5% 절감 측정
- [99-evaluation-framework.md §5](https://github.com/ryu-qqq/ryu-qqq-wiki/blob/main/wiki/research/agent-engineering/99-evaluation-framework.md) — 신규 P0로 식별
- v0.8.0 dogfooding — work-evaluator(4)·proposal-reviewer(3) 차원 1 개선 여지 발견

## 자산별 변경

### `skills/context-preprocessor/SKILL.md` — 신규

- **변경**: 코드 메타데이터 전처리 skill 신설. 입력(intent + target) → 스택 가이드 적용 → 출력 JSON. 스택 미설정·팩 없으면 fallback
- **개선**: 호출자(feedback-loop·work-evaluator·proposal-reviewer 등)가 원본 코드 자율 탐색 → 정제 메타데이터로 전환. 차원 1 (Context Efficiency) 보편 향상 기대
- **동기**: dogfooding에서 모든 평가 자산이 *"무거운 탐색"* 패턴 보유. 토큰·환각·tool call 비용 해결

### `references/java-spring/preprocessor/` — 신규 디렉토리

- `api-endpoints.md` — `@RestController` 매핑 정규식 + JSON 출력 예시 (~92% 절감 실증)
- `domain-classes.md` — 도메인·DTO·엔티티 추출 + Lombok boilerplate 제외 (~88% 절감 실증)
- `_fallback.md` — intent 매칭 실패 시 스택 무관 가벼운 인덱스
- **개선**: 스택별 가이드 분리로 본 skill 코어는 generic 유지. 다른 스택은 점진 추가

### `agents/work-evaluator.md` · `agents/proposal-reviewer.md` — 본문 한 줄 추가

- **변경**: "다른 에이전트와의 관계" 섹션에 `→ context-preprocessor (권장)` 한 줄 추가
- **개선**: 무거운 탐색 시 호출 권고. 정확 비교 필요할 때만 원본 Read 폴백
- **의도된 작은 변경**: 기존 워크플로 강제 변경 X. 자산이 알아서 선택

## 한계 (의도된)

- **AST 미사용 (v0.9.0)** — 정규식·Grep 기반. AST 기반(Java Parser 등)은 후속 버전
- **자바·스프링만 지원** — kotlin-spring·python-django 등은 별도 references 팩 추가 필요. Fallback은 약함
- **intent 해석은 LLM** — `intent: custom` 시 비결정성 발생. 차원 4 채점 시 명시
- **원본 코드 폴백 필요** — 코너 케이스(상속·복잡 제네릭·WebFlux 등)는 정규식이 놓침. 호출자가 정확 비교 필요 시 원본 Read
