# v0.10.0 — 하네스 creator (skill·agent 저작 오케스트레이터 + 보조 에이전트) (MINOR)

- **검증 상태**: 미검증 (태그는 ops-pilot 검증 후 — VERSIONING.md "검증 후 태그")

> 이 파일은 `releases/TEMPLATE.md`를 복사해 채운다. 작성·태그 절차는 VERSIONING.md "릴리스 기록" 참조.

## 이 릴리스는

터미널에서 하네스 자산(skill·agent)을 **제대로 엔지니어링해 저작**하는 도구를 추가합니다.
OpsPilot 역할 분리(저작=터미널/agent-crew, 평가·사용량·prune=ops-pilot) 방향에 따라,
플러그인 skill-creator의 **저작 부분만** 차용하고 평가는 ops-pilot에 위임합니다
(skill-creator의 grader·baseline·trigger-eval·benchmark는 ops-pilot이 이미 구현).

## 자산별 변경

### `skills/harness-creator/SKILL.md` — 신규

- **변경**: skill·agent 저작 오케스트레이터 신규. 의도 포착 → 선례 조회 → 종류·위치 판단(공통 vs 프로젝트 전용) → 저작 위임 → 구조화 커밋 → ops-pilot 평가 핸드오프.
- **개선**: 신규. 그동안 하네스 저작은 임시방편(직접 작성)이었고 평가 연계가 없었습니다. 이 스킬은 저작을 파이프라인화하고 ops-pilot 평가로 닫습니다.
- **동기**: agent-crew에 creator류 부재 → 새 자산 저작이 일관되지 않고 trigger/품질 검증과 단절. "평가는 ops-pilot" 컨셉을 저작 측에서 강제할 진입점 필요.

### `agents/harness-author.md` — 신규

- **변경**: 자산 본문 초안 저작 전담 에이전트. 종류별(skill/agent) 구조, 프로젝트 비종속 강제, `{placeholder}` 패턴.
- **개선**: 신규. 본문 저작을 description 설계·평가와 분리해 단일 책임화.
- **동기**: "여러 에이전트 조합으로 제대로 엔지니어링" — 오케스트레이터 단독보다 저작 책임을 떼어내야 품질·재사용이 는다.

### `agents/harness-trigger-designer.md` — 신규

- **변경**: description·트리거 키워드 설계 + should/should-not 예시 쿼리 산출(ops-pilot trigger-eval 입력 후보).
- **개선**: 신규. under-trigger 방지·near-miss 경계 노하우(skill-creator 차용)를 저작 단계에 주입.
- **동기**: 트리거 정확도는 ops-pilot가 *측정*하지만, 잘 *설계*된 description이 입력이어야 측정이 의미 있습니다.

## 설계 결정

- **평가 비포함**: creator는 trigger 정확도·grade·baseline을 *실행하지 않습니다*. ops-pilot이 이미 그 기능을 가지므로 중복 구현은 역할 분리를 깹니다. creator는 잘 설계된 입력(자산 본문 + 예시 쿼리)을 만들고 ops-pilot에 넘깁니다.
- **멀티에이전트**: 오케스트레이터(skill) + 저작 보조 2(author·trigger-designer). 품질 검토는 별도 자산을 더 만들지 않고 ops-pilot asset-lint·proposal-reviewer 재사용.
- **범위**: 1차는 skill·agent. command·cursor_rule은 동일 틀로 후속.
