## 이 릴리스는

세 개의 공통 파이프라인이 한 번에 들어왔습니다:

- **테스트 전략** — 기능·스펙에서 테스트 시나리오를 도출하고 테스트 피라미드(단위·슬라이스·통합·e2e)에 매핑한 계획을 만듭니다. 제네릭 코어 + Java/Spring `references` 팩.
- **ADR 의사결정** — 기능·기술 결정을 *조사 → ADR 문서화 → 결정(HITL) → 확정 → 결정 기록*으로 잇습니다. ADR은 in-repo `docs/adr/`.
- **작업 평가** — 완료 작업을 "작업 원칙 4줄"로 채점하고 vault `raw/`에 `evaluation` 시드로 기록합니다.

## 설계 결정

- 세 파이프라인 모두 **단일책임 에이전트 + 스킬 진입점** 패턴 (모놀리식 파이프라인 에이전트 지양 — 토스 글 "Slash Command = Controller").
- **스택 특화는 references 팩으로 분리** (제네릭 코어 + Progressive Disclosure). 첫 팩 `java-spring`. CLAUDE.md에 "스택 특화 ≠ 프로젝트 종속"을 명문화했습니다.
- ADR은 **in-repo `docs/adr/`** — 고전적 컨벤션이고, 코드와 함께 버전·PR에서 보입니다.
- ADR의 **결정 단계는 HITL** — 에이전트가 대신 결정하지 않습니다 (토스 글 "Exception이 Question으로").
- work-evaluator는 **"파이프라인 끝 자기 채점"** — 훅-인터셉터(런타임 관측, ops-pilot 영역) 대신입니다. 귀인은 구조적으로(파이프라인별 1:1), 신호품질은 의도적 자기평가로 해결합니다.
- 작업 평가의 **4원칙은 CLAUDE.md에도** 자산 저작 원칙으로 명문화했습니다 (idea.txt 흡수). 단일 출처입니다.
- work-evaluator의 파이프라인 배선(`test-plan`·`/adr` 마지막 단계 호출)은 다음입니다 — 4원칙이 코드 중심이라 *구현 파이프라인*이 주 타깃이고, 그게 생길 때 함께 합니다.
