## 이 릴리스는

기능·스펙에서 테스트 계획을 수립하는 **테스트 전략 레이어**를 추가했다. 시나리오 도출과
테스트 피라미드 매핑을 담당하며, 스택 특화 메커니즘은 references 팩으로 분리했다.
이번 범위는 *계획·전략*까지 — 테스트 코드 생성·실행은 포함하지 않는다.

## 설계 결정

- 테스트 파이프라인을 **단일책임 에이전트(test-strategist) + 스킬 진입점(test-plan)**으로 구성. 모놀리식 파이프라인 에이전트는 지양 (레포 패턴·SRP, 토스 글 "Slash Command=Controller, Sub-agent=Service").
- 이번 범위는 **테스트 계획·전략**까지. 테스트 코드 생성·실행은 별도 후속.
- 스택 특화 지식은 **`references/<stack>/` 팩**으로 분리 (제네릭 코어 + Progressive Disclosure). 에이전트는 `project.stack`을 읽어 팩을 로드 — 스택 미설정이면 스택 무관 계획으로 폴백.

## 호환성

- **project.yaml**: `project.stack` 추가 — 선택적, 미설정 시 스택 무관 동작.
- **마이그레이션**: 불필요. Java/Spring 프로젝트는 `project.stack: java-spring`을 넣으면 스택 특화 권고를 받는다.
