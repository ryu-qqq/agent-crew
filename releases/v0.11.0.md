## 이 릴리스는

OpsPilot 평가 **"설계(생성)"** 로직을 agent-crew 하네스 자산으로 이관하는
[ops-pilot ADR 0002](https://github.com/ryu-qqq/ops-pilot/blob/main/docs/adr/0002-eval-design-to-agent-crew.md)의
후속작업 1을 반영합니다. 그동안 ops-pilot 백엔드에 baked TS 프롬프트로 박혀 있던
평가 입력 생성 로직(시나리오·성공조건·description 개선)을 자산화해, **agent-crew = 설계 원본,
ops-pilot = 소비·측정** 역할분담을 코드 차원에서 회복합니다. 측정(probe·run·score)은
ops-pilot에 결정적으로 남습니다 — 이 릴리스는 *설계* 자산만 다룹니다.

ADR 결정 3C에 따라 ① 트리거 쿼리·② description 개선은 기존 `harness-trigger-designer`를
재사용(본문 확장)하고, ③ 시나리오 + ④ 성공조건은 신규 `scenario-designer` 1개로 통합합니다
(input과 assertions가 `scenarioSchema`에서 한 쌍이라 응집도가 높습니다).

## 자산별 변경

### `agents/scenario-designer.md` — 신규

- **변경**: OpsPilot 평가용 시나리오(input) + 성공조건(assertions/expectation)을 한 쌍으로 통합 생성하는 피호출 에이전트. JSON 한 객체 `{name, purpose, input, expectedBehavior, successCriteria[]}` 산출. `agent-evaluator`/`work-evaluator` 계열 구조.
- **개선**: 신규. 그동안 시나리오·성공조건 생성은 ops-pilot `assist/scenario-suggest.ts`의 baked TS 프롬프트였습니다 — 자산화로 sync 진화·도그푸딩이 성립합니다.
- **동기**: ADR 0002 결정 3C — ③④는 동반 생성 한 쌍이라 통합 에이전트가 자연스럽습니다.
- **설계 못박음**: ⓐ 출력 SSOT = ops-pilot `packages/shared-types` zod(`scenarioSchema`·`expectationSchema`)·`scenarioSuggestionSchema`, 본문은 요약+참조만(2C). ⓑ MCP 비종속(portable) — 티켓 맥락은 ops-pilot 어댑터가 텍스트로 정규화해 주입(5C). ⓒ `allowed-tools: [Read]` — 자산 본문은 주입받으므로 project.yaml Read만 필요.

### `agents/harness-trigger-designer.md` — 본문 확장 (description 개선 모드 추가)

- **변경**: 기존 "신규 설계 모드"(description·트리거 쿼리 설계)에 더해 **"description 개선 모드 (실패 사례 피드백)"** 절 추가. 입력에 실패 사례(`[{query, expected, actual}]`)가 오면 개선 모드로 분기.
- **개선**: ops-pilot `trigger-eval/service.ts`의 baked `improveDescription`/`improveDescriptionLoop` 중 **LLM 개선 한 스텝**을 자산으로 이관. false negative→트리거 신호 보강, false positive→경계 강화, 과교정 금지·최소 수정 원칙 명시.
- **동기**: ADR 0002 결정 3C(②는 기존 trigger-designer 재사용) + 결정 3(반복 루프·train/test 분할은 ops-pilot, 자산은 한 스텝만).
- **불변**: frontmatter `description`·기존 절(신규 설계 모드) 손대지 않음 — 절 1개만 삽입합니다.

## 설계 결정 (ADR 0002 채택 요약)

- **1B 본문 주입**: 자산 `.md` 본문을 `claude -p` 프롬프트로 직접 주입. 결정성이 baked와 동등, 코드 변경 최소. 순수 도그푸딩(1A 자연 트리거)은 약화하되 "자산=로직"은 유지.
- **2C, SSOT = shared-types zod**: 자산 본문은 스키마 요약+참조, 강제 검증은 ops-pilot zod. drift 최소화.
- **3C 자산 구성**: ①② trigger-designer 재사용, ③④ scenario-designer 통합 신규.
- **4B 격하·fallback**: ops-pilot이 자산 호출을 우선하되 실패 시 baked fallback. 자산 vs baked A/B로 자가편향 외부 검증. **측정 러너(probe·run·score) 불변** — "새 러너 금지".
- **5C 입력 어댑터**: MCP 티켓 조회는 ops-pilot에 격리, 자산엔 정규화 텍스트만 → 자산 portable 유지.
