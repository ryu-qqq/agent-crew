# v0.14.0 — abstraction-critic + shared-SDK 추상화 리뷰 rubric (MINOR)

- **날짜**: 2026-06-08
- **유형**: MINOR
- **이전**: v0.13.0
- **검증 상태**: **미검증** — rubric은 cross-module 감사(dogfooding)에서 도출됐으나, `abstraction-critic` 에이전트 자체의 trigger-eval·시나리오 grade·baseline은 ops-pilot 별도(아래 "검증 입력 후보").

> 이 파일은 `releases/TEMPLATE.md`를 복사해 채운다. 작성·태그 절차는 VERSIONING.md "릴리스 기록" 참조.

## 이 릴리스는

공유 SDK로 끌어올리는 **공개 추상화가 "올바른 공용 추상화인가"를 보는 설계 게이트**를 자산화한다.

그동안 "이 port/SPI/DTO를 공용으로 뽑는 게 맞나"라는 판단은 매 모듈마다 오케스트레이터가 즉흥 추론했다 — 일관성도 재현성도 없었다. 실제로 그 즉흥 판단이 늦게 작동해, 한 SDK 추상화가 트랜스포트("Queue")를 이름·SPI에 박고 어댑터가 매퍼+리포+트랜스포트 3역을 융합한 채 머지된 사례가 있었다.

이 릴리스는 그 판단을 **6축 rubric**(commonality·seam·isp·neutrality·yagni·conventions)으로 명문화하고, 그것을 실행하는 `abstraction-critic` 에이전트를 추가한다. rubric의 운영 체크(N·S·C·I·Y·V)는 상상이 아니라, 한 모노레포의 기존 SDK 모듈 11개를 병렬 감사해 **반복 검출된 동형 패턴**을 측정가능한 신호로 환원한 것이다.

핵심 설계: **레버리지는 코드 작성 전 설계 앞단**이다. 추상화의 치명적 실수는 "애초에 이렇게 추상화하면 안 됐다"라 PR 코드리뷰로는 늦다.

## 자산별 변경

### `references/conventions/shared-sdk-abstraction-review.md` — 신규

- **변경**: 공유 SDK 공개 추상화 채점의 SSOT. 6축 정의 + 축별 운영 체크포인트(N1~3·S1~3·C1~3·I1~2·Y1~2·V1~3) + 판정 기준(CLEAN/CONCERN/REDESIGN) + "rubric의 한계" 정직성 섹션.
- **동기**: "공용성 판단"이 매 모듈 ad-hoc 추론이라 일관·재현 불가. cross-module 감사로 같은 부류 문제(구현명 박힘·seam 융합·앱특화 누수·@Component 단독·god SPI·주석 동기화)가 반복됨을 확인 → 체크로 고정.
- **설계 못박음**: ⓐ **SSOT 분리** — rubric이 측정 항목의 단일 출처, 에이전트는 실행만(asset-quality-rubric ↔ agent-evaluator와 동형). ⓑ 축 1(commonality)은 한 레포로 판단 불가 → decision-researcher의 서버교차 스캔이 보조한다고 명시. ⓒ "1소비자뿐이면 수렴이 아니라 승격으로 분류" 같은 교훈을 체크(C3)로 박음.

### `agents/abstraction-critic.md` — 신규

- **변경**: 대상 추상화(설계 초안 또는 기존 모듈 공개 표면)를 6축 rubric으로 채점해 findings(JSON) 반환. read-only, 비평 전담.
- **개선**: 신규. resilience-reviewer(특정 SDK 코드 버그)·agent-evaluator(하네스 자산 8차원)와 **직교** — 공용 추상화 아키텍처 seam 축을 보는 자산이 없던 갭을 채운다.
- **동기**: 설계 게이트가 사람·즉흥 추론에 의존하면 일관성이 무너진다. 플랫폼·공통 라이브러리 모듈이 늘수록 재발하는 판단이라 공유 자산이 적합.
- **설계 못박음**: ⓐ **프로젝트 비종속** — 본문에 절대경로·특정 프로젝트명 없이 "공유 SDK/공개 추상화" 일반 용어 + `{placeholder}`. ⓑ **수정 금지**(read-only) — 코드·설계 파일 미변경. ⓒ **버그·스타일 범위 외** — 일반 결함은 스택 reviewer 몫, 여긴 seam만. ⓓ **자가 채점으로 release/머지 결정 X** — 평가·태그는 ops-pilot, 최종 판단은 사람. ⓔ findings는 file:line 구체 근거 필수.
