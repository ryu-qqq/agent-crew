# v0.13.0 — tf-import 스킬 (기존 AWS 리소스 0-diff 입양) (MINOR)

- **날짜**: 2026-06-05
- **유형**: MINOR
- **이전**: v0.12.0
- **검증 상태**: **첫 실전 검증 통과(dogfooding)** — `platform-bootstrap` 네트워크 입양에서 게이트가 SG `description` 변경(태그 외)을 STOP→보정→0-diff로 안내, `26 imported · 20 changed · 0 destroyed` 무중단 입양 성공. ops-pilot trigger-eval·시나리오 grade는 별도 미검증(아래 "검증 입력 후보").

> 이 파일은 `releases/TEMPLATE.md`를 복사해 채웁니다. 작성·태그 절차는 VERSIONING.md "릴리스 기록" 참조.

## 이 릴리스는

agent-crew 최초의 **인프라 "실행 절차" 자산**입니다. 그동안 `references/infra-aws/`는
정적 컨벤션(레이아웃·게이트·티어 정의)만 담았고, terraform import·plan 게이트·태깅처럼
*반복되고 위험한 절차*를 안내·검증하는 자산은 없었습니다. `tf-import`가 그 갭의 첫 사례입니다.

이미 콘솔·CLI로 존재하는 AWS 리소스를 0-diff로 terraform state에 입양하는 워크플로를
스킬 하나로 묶습니다. 핵심은 **plan 게이트** — import 후 plan이 "태그 추가만"인지 검증하고,
태그 외 modify·recreate·destroy가 하나라도 보이면 STOP합니다. 공유 인프라(다수 prod 스택이
물린 VPC 등)일수록 무중단 입양을 깨는 recreate·destroy를 게이트에서 막는 것이 존재 이유입니다.

## 자산별 변경

### `skills/tf-import/SKILL.md` — 신규

- **변경**: 기존 AWS 리소스를 terraform state로 0-diff 입양하는 사용자 진입점·절차 오케스트레이터. 8단계 — 대상 확인 → 인벤토리 live 조회(read-only) → raw config 미러링 → init(HITL) → import(HITL) → **plan 게이트**(read-only) → 태그-only apply(HITL) → 커밋. 게이트 판정을 스킬 내 단계로 내장(별도 에이전트 미분리).
- **개선**: 신규. 인프라 실행 절차가 그동안 매 작업의 ad-hoc TODO 문서에 흩어져 있었습니다 — 자산화로 sync·도그푸딩·평가가 성립합니다.
- **동기**: 위험한 import 작업의 안전 게이트("태그 외 변경 STOP")가 사람이 놓치기 쉬운 지점이고, 인프라 프로젝트(platform-bootstrap·platform-gitops·terraform-modules) 공통으로 재발하는 패턴이라 공유 자산이 적합합니다.
- **설계 못박음**: ⓐ **프로젝트 비종속** — 절대경로·리소스 ID·계정·리전·프로젝트명 없이 placeholder/"대상 프로젝트에서 정한다". ⓑ **HITL 경계** = real backend init·import·apply는 사용자 확인(`references/infra-aws/governance-gates.md`), describe·validate(`-backend=false`)·plan·config 작성은 read-only. ⓒ **SSOT = live 값** — wiki·README·추정 금지(`tier-policy.md` F3 룰). ⓓ required 태그는 provider `default_tags`에 둬 게이트에서 "태그 추가"가 깨끗이 드러나게 합니다.

### 검증 입력 후보 — 트리거 정확도 (ops-pilot trigger-eval)

should-trigger:
- "이 VPC랑 서브넷들 terraform으로 import 하자"
- "콘솔로 만들어둔 prod NAT 게이트웨이를 terraform state에 입양시켜줘"
- "수동으로 만든 IAM 역할이랑 endpoint를 IaC로 흡수하고 싶은데 0-diff로 가능해?"
- "기존 인프라 terraform import 안전하게 하는 법 알려줘, recreate 나면 큰일나"
- "vpc-xxxx 이거 지금 운영 중인데 terraform 관리로 가져오게 해줘"
- "콘솔에서 만든 리소스들 terraform state에 넣고 태그만 붙여서 관리하게 마이그레이션해줘"

should-not (near-miss):
- "새 staging VPC랑 서브넷 terraform 모듈 새로 짜서 apply 해줘" (신규 생성)
- "이미 terraform으로 관리 중인 보안그룹 인바운드 규칙 하나 추가하고 plan 돌려줘" (일반 운영)
- "terraform plan이 drift 나는 이유 좀 디버깅해줘" (drift 디버깅)
- "이 tf 모듈 PR 리뷰해줘, IAM 권한 위주로 봐줘" (코드 리뷰)
- "aws cli로 현재 prod에 떠 있는 NAT 게이트웨이 목록만 뽑아줘" (단순 조회)
- "terraform state 관리 전략 ADR로 정리하고 싶어, 어떻게 결정하지" (ADR 결정)
