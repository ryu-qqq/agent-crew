# v0.4.0 — Engineering OS 작업 루프

- **날짜**: 2026-05-25
- **유형**: MINOR
- **이전**: v0.3.0
- **검증 상태**: 미검증

> Notion Engineering OS(Tasks / Projects / Epics)와 wiki·git Commit을 한 작업 단위로 묶는 convention·스킬 추가.
> Jira 대신 Notion 백로그를 쓰는 소비 프로젝트(ops-pilot pivot 등)용.

## 이 릴리스는

Engineering OS를 agent-crew의 **공통 메타 운영 convention**으로 formalize합니다.
`notion-manager`가 status·Wiki ADR·Commit 갱신을 convention-aware로 수행하고,
`engineering-os` 스킬이 일상 작업 시작·완료 루프를 오케스트레이션합니다.

## 자산별 변경

### `skills/engineering-os/SKILL.md` — 신규

- **변경**: Notion Task 시작(`eo-start`)·완료(`eo-done`)·조회. `notion-manager`·journal·wiki·adr·work-evaluator 위임.
- **동기**: Engineering OS 허브 구축 후, Cursor/Claude가 같은 필드 규칙으로 Task·wiki·Commit을 갱신해야 합니다.

### `references/notion/engineering-os.md` — 신규

- **변경**: Tasks DB 권장 속성, status 전이, 완료 시 Wiki ADR·Commit, vault와 역할 분담.
- **동기**: Notion DB freeform 전제 하에 **공유 convention** 문서가 필요합니다.

### `agents/notion-manager.md` — 개선

- **변경**: `convention: engineering-os`·`fieldNames`·완료 시 Wiki ADR/Commit 절차. engineering-os 스킬과의 관계.
- **개선**: Jira-style status表와 Engineering OS status表가 공존합니다 — DB fetch 우선입니다.

### `project.yaml.example` — 수정

- **변경**: `tracking.notion`에 hubPageUrl, projects/epics DB, convention, fieldNames 추가. jira 기본 false 예시.
- **개선**: additive — 기존 소비 프로젝트는 수정이 불필요합니다.

### `README.md` — 수정

- **변경**: `engineering-os` 스킬·`references/notion/` 반영.
